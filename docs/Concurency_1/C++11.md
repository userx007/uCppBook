# C++11 Concurrency: Complete Reference

C++11 introduced a standardized concurrency model to the language for the first time (before this, threading relied on platform APIs like pthreads or Win32 threads, or libraries like Boost.Thread). This guide covers every major concurrency element added in C++11, with small examples for each.

Headers involved: `<thread>`, `<mutex>`, `<condition_variable>`, `<atomic>`, `<future>`, `<chrono>`.

Compile examples with: `g++ -std=c++11 -pthread file.cpp`

---

## 1. `std::thread` — Creating and Managing Threads

The fundamental building block. Wraps a native OS thread.

```cpp
#include <iostream>
#include <thread>

void worker(int id) {
    std::cout << "Worker " << id << " running\n";
}

int main() {
    std::thread t1(worker, 1);   // launch thread, pass args
    std::thread t2([] {          // lambda works too
        std::cout << "Lambda thread running\n";
    });

    t1.join();   // wait for t1 to finish
    t2.join();   // wait for t2 to finish
}
```

Key members:

- `.join()` — blocks until the thread finishes.
- `.detach()` — thread runs independently; you lose the ability to join it.
- `.joinable()` — check whether the thread can still be joined/detached.
- `.get_id()` — returns a `std::thread::id`.
- `std::thread::hardware_concurrency()` — hint at number of cores.

A `std::thread` object **must** be joined or detached before it's destroyed, or `std::terminate()` is called.

```cpp
std::thread t(worker, 2);
if (t.joinable()) t.detach();
```

## 2. `std::mutex` and Friends — Mutual Exclusion

Header `<mutex>` provides several lock types to protect shared data.

### `std::mutex`

```cpp
#include <mutex>
#include <thread>
#include <iostream>

std::mutex mtx;
int counter = 0;

void increment() {
    for (int i = 0; i < 100000; ++i) {
        mtx.lock();
        ++counter;
        mtx.unlock();
    }
}

int main() {
    std::thread t1(increment), t2(increment);
    t1.join(); t2.join();
    std::cout << counter << "\n"; // always 200000
}
```

Manually calling `lock()`/`unlock()` is error-prone (exceptions skip the unlock). Prefer RAII wrappers:

### `std::lock_guard` — simple RAII lock

```cpp
void increment_safe() {
    for (int i = 0; i < 100000; ++i) {
        std::lock_guard<std::mutex> lock(mtx); // locks on construction
        ++counter;
    } // unlocks automatically when 'lock' goes out of scope
}
```

### `std::unique_lock` — flexible RAII lock

Supports deferred locking, manual unlock/relock, and is required by `condition_variable::wait`.

```cpp
std::unique_lock<std::mutex> lock(mtx, std::defer_lock); // don't lock yet
lock.lock();
// ... critical section ...
lock.unlock();
// ... non-critical work ...
lock.lock();
```

### Other mutex types

- `std::recursive_mutex` — same thread may lock it multiple times.
- `std::timed_mutex` / `std::recursive_timed_mutex` — support `try_lock_for()` / `try_lock_until()`.

```cpp
std::timed_mutex tmtx;
if (tmtx.try_lock_for(std::chrono::milliseconds(50))) {
    // got the lock within 50ms
    tmtx.unlock();
}
```

### `try_lock()` — non-blocking lock attempt

Every mutex type (`mutex`, `recursive_mutex`, `timed_mutex`, etc.) also has a non-blocking `try_lock()`, which returns `true` if it acquired the lock and `false` immediately if it couldn't.

```cpp
if (mtx.try_lock()) {
    // got the lock without waiting
    mtx.unlock();
} else {
    // someone else holds it; do something else instead
}
```

### `std::lock` — deadlock-free multi-mutex locking

Locking two mutexes independently can deadlock if two threads acquire them in opposite order. `std::lock` locks several mutexes atomically using a deadlock-avoidance algorithm.

```cpp
std::mutex m1, m2;

void transfer() {
    std::lock(m1, m2);                                  // locks both, no deadlock
    std::lock_guard<std::mutex> lk1(m1, std::adopt_lock); // adopt already-locked mutex
    std::lock_guard<std::mutex> lk2(m2, std::adopt_lock);
    // ... safe to use both resources ...
}
```

### `std::call_once` / `std::once_flag`

Guarantees a function runs exactly once, even if called from many threads concurrently — the standard way to do thread-safe lazy initialization.

```cpp
#include <mutex>

std::once_flag flag;

void init() { std::cout << "Initialized once\n"; }

void thread_func() {
    std::call_once(flag, init); // only the first caller actually runs init()
}
```

## 3. `std::condition_variable` — Waiting for a Condition

Lets threads block until notified by another thread, avoiding busy-waiting. Always used with a `std::unique_lock<std::mutex>`.

```cpp
#include <condition_variable>
#include <queue>

std::mutex mtx;
std::condition_variable cv;
std::queue<int> data_queue;
bool finished = false;

void producer() {
    for (int i = 0; i < 5; ++i) {
        {
            std::lock_guard<std::mutex> lock(mtx);
            data_queue.push(i);
        }
        cv.notify_one(); // wake one waiting thread
    }
    { std::lock_guard<std::mutex> lock(mtx); finished = true; }
    cv.notify_one();
}

void consumer() {
    while (true) {
        std::unique_lock<std::mutex> lock(mtx);
        cv.wait(lock, [] { return !data_queue.empty() || finished; }); // sleeps until predicate is true
        while (!data_queue.empty()) {
            std::cout << "Consumed " << data_queue.front() << "\n";
            data_queue.pop();
        }
        if (finished) break;
    }
}

int main() {
    std::thread p(producer), c(consumer);
    p.join(); c.join();
}
```

- `wait(lock, predicate)` — unlocks the mutex, sleeps, and on wake re-checks the predicate (guards against spurious wakeups).
- `notify_one()` — wakes a single waiting thread.
- `notify_all()` — wakes all waiting threads.
- `wait_for()` / `wait_until()` — wait with a timeout.

### `std::cv_status`

The enum returned by `wait_for()`/`wait_until()` (when not using the predicate overload), telling you whether the wait ended due to a timeout or a notification.

```cpp
std::unique_lock<std::mutex> lock(mtx);
if (cv.wait_for(lock, std::chrono::milliseconds(100)) == std::cv_status::timeout) {
    std::cout << "Timed out waiting\n";
} else {
    std::cout << "Woken by notify\n";
}
```

### `std::condition_variable_any`

Same interface as `std::condition_variable`, but works with *any* lock type that meets the BasicLockable requirement (not just `std::unique_lock<std::mutex>`) — e.g. a custom lock class or `unique_lock<recursive_mutex>`. Slightly more overhead than `condition_variable`, so prefer the plain version unless you need this flexibility.

```cpp
std::recursive_mutex rmtx;
std::condition_variable_any cv_any;

void wait_with_recursive_mutex() {
    std::unique_lock<std::recursive_mutex> lock(rmtx);
    cv_any.wait(lock, [] { return /* some condition */ true; });
}
```

## 4. `std::atomic` — Lock-Free Shared Variables

Header `<atomic>` provides types where operations (read, write, read-modify-write) are guaranteed indivisible, without needing a mutex.

```cpp
#include <atomic>
#include <thread>

std::atomic<int> counter(0);

void increment() {
    for (int i = 0; i < 100000; ++i)
        counter.fetch_add(1, std::memory_order_relaxed); // atomic increment
}

int main() {
    std::thread t1(increment), t2(increment);
    t1.join(); t2.join();
    std::cout << counter.load() << "\n"; // always 200000, no mutex needed
}
```

Key operations: `.load()`, `.store()`, `.exchange()`, `.compare_exchange_weak()/strong()`, `.fetch_add()`, `.fetch_sub()`, and operators like `++`, `--`, `+=`.

### `std::atomic_flag`

The only atomic type guaranteed lock-free on all platforms; useful for building simple spinlocks.

```cpp
std::atomic_flag lock_flag = ATOMIC_FLAG_INIT;

void spinlock_acquire() {
    while (lock_flag.test_and_set(std::memory_order_acquire)) {
        // spin until we acquire the flag
    }
}

void spinlock_release() {
    lock_flag.clear(std::memory_order_release);
}
```

### Memory Ordering

C++11 defines a memory model with orderings you can specify per atomic operation:

| Ordering | Meaning |
| --- | --- |
| `memory_order_relaxed` | Only atomicity guaranteed; no ordering constraints |
| `memory_order_acquire` | No reads/writes after this can be reordered before it |
| `memory_order_release` | No reads/writes before this can be reordered after it |
| `memory_order_acq_rel` | Combines acquire + release |
| `memory_order_seq_cst` | Sequentially consistent — default, strongest, easiest to reason about |

```cpp
std::atomic<bool> ready(false);
std::atomic<int> value(0);

void writer() {
    value.store(42, std::memory_order_relaxed);
    ready.store(true, std::memory_order_release); // publish
}

void reader() {
    while (!ready.load(std::memory_order_acquire)); // synchronize
    std::cout << value.load(std::memory_order_relaxed) << "\n"; // guaranteed to see 42
}
```

### `std::atomic_thread_fence` / `std::atomic_signal_fence`

Standalone memory barriers that impose ordering constraints without being attached to a specific atomic variable. `atomic_thread_fence` orders memory across threads; `atomic_signal_fence` only orders against signal handlers on the same thread (no actual CPU instruction emitted).

```cpp
#include <atomic>

int data = 0;
std::atomic<bool> ready(false);

void writer() {
    data = 42;
    std::atomic_thread_fence(std::memory_order_release); // ensure 'data' write is visible before...
    ready.store(true, std::memory_order_relaxed);
}

void reader() {
    while (!ready.load(std::memory_order_relaxed));
    std::atomic_thread_fence(std::memory_order_acquire); // ...this read happens
    std::cout << data << "\n"; // guaranteed to see 42
}
```

### Named atomic typedefs

C++11 provides convenience aliases for `std::atomic<T>` over common built-in types, so you don't have to spell out the template argument:

```cpp
std::atomic_int    a{0};   // same as std::atomic<int>
std::atomic_bool   b{false};
std::atomic_size_t c{0};
std::atomic_long   d{0};
// ...and similarly for char, short, long long, and their unsigned variants
```

## 5. `std::future` / `std::promise` — One-Shot Value Transfer

Header `<future>` lets one thread compute a value and another thread retrieve it later, with built-in synchronization.

### `std::promise` + `std::future`

```cpp
#include <future>

void compute(std::promise<int> prom) {
    int result = 6 * 7;
    prom.set_value(result); // sets the value; unblocks the future
}

int main() {
    std::promise<int> prom;
    std::future<int> fut = prom.get_future();

    std::thread t(compute, std::move(prom));
    std::cout << "Result: " << fut.get() << "\n"; // blocks until set_value() is called
    t.join();
}
```

- `fut.get()` — blocks until the value is ready, then returns it (callable only once).
- `fut.wait()` — blocks without retrieving the value.
- `fut.wait_for(duration)` / `wait_until(time_point)` — wait with a timeout, returns a `std::future_status`.
- Exceptions can be propagated via `prom.set_exception(std::current_exception())`, then rethrown on `.get()`.

### `std::async` — Simplest Way to Run a Task Asynchronously

```cpp
#include <future>

int compute_square(int x) {
    return x * x;
}

int main() {
    std::future<int> fut = std::async(std::launch::async, compute_square, 12);
    // do other work here while it computes...
    std::cout << "Square: " << fut.get() << "\n"; // 144
}
```

Launch policies:

- `std::launch::async` — forces execution on a new thread.
- `std::launch::deferred` — runs lazily, on the calling thread, only when `.get()`/`.wait()` is called.
- Default (`async | deferred`) — implementation chooses.

### `std::packaged_task` — Wrap a Callable to Get a Future

Useful when you want to decouple task creation from execution (e.g., pushing into a thread pool queue).

```cpp
#include <future>

int add(int a, int b) { return a + b; }

int main() {
    std::packaged_task<int(int, int)> task(add);
    std::future<int> fut = task.get_future();

    std::thread t(std::move(task), 3, 4); // task runs on this thread
    t.join();

    std::cout << "Sum: " << fut.get() << "\n"; // 7
}
```

### `std::shared_future` — Multiple Consumers

A `std::future` can only be consumed once (`.get()` invalidates it). `std::shared_future` allows several threads to read the same result.

```cpp
std::promise<int> prom;
std::shared_future<int> sfut = prom.get_future().share();

auto reader = [sfut] { std::cout << sfut.get() << "\n"; }; // copyable, each can call get()

std::thread t1(reader), t2(reader);
prom.set_value(99);
t1.join(); t2.join();
```

### `std::future_error` / `std::future_errc`

The exception type thrown by future/promise operations when misused, carrying an error code from the `std::future_errc` enum.

```cpp
std::promise<int> prom;
std::future<int> fut1 = prom.get_future();

try {
    std::future<int> fut2 = prom.get_future(); // already retrieved!
} catch (const std::future_error& e) {
    std::cout << "Error: " << e.what() << "\n";
    if (e.code() == std::future_errc::future_already_retrieved)
        std::cout << "-> future_already_retrieved\n";
}
```

Common `future_errc` values: `broken_promise` (promise destroyed before setting a value), `future_already_retrieved`, `promise_already_satisfied`, `no_state`.

## 6. `thread_local` Storage

A storage-duration specifier (not a class), giving each thread its own independent copy of a variable.

```cpp
#include <thread>
#include <iostream>

thread_local int counter = 0; // each thread gets its own 'counter'

void increment_and_print() {
    ++counter;
    std::cout << "Thread " << std::this_thread::get_id() << " counter = " << counter << "\n";
}

int main() {
    std::thread t1(increment_and_print);
    std::thread t2(increment_and_print);
    t1.join(); t2.join();
    // both print counter = 1, since each thread has its own copy
}
```

## 7. `std::this_thread` Namespace Helpers

Free functions operating on the calling thread.

```cpp
#include <thread>
#include <chrono>

std::this_thread::get_id();                              // this thread's id
std::this_thread::sleep_for(std::chrono::milliseconds(100)); // sleep 100ms
std::this_thread::sleep_until(std::chrono::steady_clock::now() + std::chrono::seconds(1));
std::this_thread::yield();                                // hint scheduler to run another thread
```

## 8. Minor `std::thread` Utilities

```cpp
std::thread t1(worker, 1);
std::thread t2(worker, 2);
t1.swap(t2);           // swap which underlying OS thread each object manages
std::swap(t1, t2);     // equivalent non-member form

std::thread::id id = t1.get_id();
std::hash<std::thread::id> hasher;
size_t h = hasher(id); // thread ids are hashable, so usable as e.g. unordered_map keys
```
