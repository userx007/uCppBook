# C++14 Concurrency: What's New

C++14 was a small, incremental release focused on refinements rather than a major concurrency overhaul (that came later, in C++17 and C++20). It added exactly **one new concurrency primitive pair** to the standard library, plus a language convenience that's very useful alongside the timed concurrency APIs.

Everything from C++11 (`thread`, `mutex`, `condition_variable`, `atomic`, `future`, etc.) carries forward unchanged — this guide only covers what's *new* in C++14.

Compile with: `g++ -std=c++14 -pthread file.cpp`

---

## 1. `std::shared_timed_mutex` — Reader/Writer Lock

Header: `<shared_mutex>`

C++11 only gave you exclusive-ownership mutexes — only one thread could hold the lock at a time, whether reading or writing. `std::shared_timed_mutex` (C++14) introduces **shared (reader) ownership** alongside exclusive (writer) ownership, implementing the classic reader-writer lock pattern: many threads can read simultaneously, but a writer needs exclusive access.

```cpp
#include <shared_mutex>
#include <thread>
#include <vector>
#include <iostream>

std::shared_timed_mutex rw_mutex;
int shared_data = 0;

void reader(int id) {
    std::shared_lock<std::shared_timed_mutex> lock(rw_mutex); // shared/read lock
    std::cout << "Reader " << id << " sees value " << shared_data << "\n";
}

void writer(int value) {
    std::lock_guard<std::shared_timed_mutex> lock(rw_mutex);  // exclusive/write lock
    shared_data = value;
    std::cout << "Writer set value to " << value << "\n";
}

int main() {
    std::vector<std::thread> threads;
    threads.emplace_back(writer, 1);
    for (int i = 0; i < 5; ++i)
        threads.emplace_back(reader, i);       // multiple readers can run concurrently
    threads.emplace_back(writer, 2);

    for (auto& t : threads) t.join();
}
```

Key operations:

- `.lock()` / `.unlock()` — exclusive (write) lock, same as a normal mutex.
- `.lock_shared()` / `.unlock_shared()` — shared (read) lock; multiple threads can hold it at once.
- `.try_lock()` / `.try_lock_shared()` — non-blocking attempts.
- `.try_lock_for()` / `.try_lock_until()` — timed exclusive lock attempts.
- `.try_lock_shared_for()` / `.try_lock_shared_until()` — timed shared lock attempts.

The "timed" in the name means it supports timeout-based locking (`try_lock_for`/`try_lock_until`), unlike the plain `std::shared_mutex` that was later added in C++17 without timing support.

## 2. `std::shared_lock` — RAII Wrapper for Shared Ownership

Header: `<shared_mutex>`

Just as `std::lock_guard`/`std::unique_lock` are RAII wrappers for exclusive locks, `std::shared_lock` is the RAII wrapper for the shared-ownership side of `shared_timed_mutex`. It acquires a shared lock on construction and releases it on destruction.

```cpp
#include <shared_mutex>

std::shared_timed_mutex mtx;

void read_safely() {
    std::shared_lock<std::shared_timed_mutex> lock(mtx); // acquires lock_shared()
    // ... read shared_data ...
} // automatically calls unlock_shared()
```

Like `unique_lock`, it also supports deferred/timed locking strategies:

```cpp
std::shared_lock<std::shared_timed_mutex> lock(mtx, std::defer_lock);
if (lock.try_lock_for(std::chrono::milliseconds(50))) {
    // got shared access within 50ms
}
```

Note there is no shared equivalent of `lock_guard` — `shared_lock` is the only RAII shared-ownership wrapper, and it's slightly heavier than `lock_guard` since it supports deferred/timed/movable semantics.

## 3. `std::chrono` Duration Literals — A Handy Companion

Header: `<chrono>` (via `using namespace std::chrono_literals;`)

Not a concurrency primitive itself, but a language feature that makes every timed concurrency call (`sleep_for`, `wait_for`, `try_lock_for`, etc.) noticeably more readable. Before C++14 you had to write `std::chrono::milliseconds(100)`; now you can write `100ms`.

```cpp
#include <chrono>
#include <thread>
#include <shared_mutex>

using namespace std::chrono_literals;

std::this_thread::sleep_for(100ms);              // instead of std::chrono::milliseconds(100)

std::shared_timed_mutex mtx;
if (mtx.try_lock_for(50ms)) {                    // reads naturally
    mtx.unlock();
}

std::condition_variable cv;
std::mutex m;
std::unique_lock<std::mutex> lock(m);
cv.wait_for(lock, 2s);                           // 2 seconds
```

Available suffixes: `h` (hours), `min` (minutes), `s` (seconds), `ms` (milliseconds), `us` (microseconds), `ns` (nanoseconds).

## Quick Summary Table

| Element | Header | Purpose |
| --- | --- | --- |
| `std::shared_timed_mutex` | `<shared_mutex>` | Reader/writer lock with timed locking support |
| `std::shared_lock` | `<shared_mutex>` | RAII wrapper for shared (read) ownership |
| `std::chrono` literals (`ms`, `s`, `us`, ...) | `<chrono>` | Concise duration syntax for timed waits/locks |

---

**Context:** that's the entire concurrency delta in C++14 — the standard committee saved the bigger concurrency additions (`std::shared_mutex` without timing, parallel algorithms, `std::latch`/`std::barrier`, atomic `shared_ptr`, etc.) for C++17 and C++20.
