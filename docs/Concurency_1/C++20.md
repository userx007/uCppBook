# C++20 Concurrency: What's New

C++20 is the biggest concurrency update since C++11 itself. It adds new thread types with cooperative cancellation, several new synchronization primitives (latches, barriers, semaphores), atomic wait/notify (letting atomics replace condition variables in many cases), atomic `shared_ptr`, and coroutines as a language-level foundation for asynchronous code. This guide covers only what's *new* in C++20, on top of C++11/14/17.

Compile with: `g++ -std=c++20 -pthread file.cpp` (as of late 2025/2026, use a recent GCC/Clang — some of these, especially coroutines and atomic `shared_ptr`, landed in standard library implementations later than the language standard itself).

---

## 1. `std::jthread` — Self-Joining, Cancellable Thread

Header: `<thread>`

Fixes two long-standing `std::thread` annoyances: forgetting to `join()` (which calls `std::terminate`), and having no built-in way to ask a thread to stop early.

```cpp
#include <thread>
#include <chrono>
#include <iostream>

void worker(std::stop_token stoken) {
    while (!stoken.stop_requested()) {
        std::cout << "Working...\n";
        std::this_thread::sleep_for(std::chrono::milliseconds(200));
    }
    std::cout << "Stop requested, exiting cleanly\n";
}

int main() {
    std::jthread t(worker);              // starts running immediately
    std::this_thread::sleep_for(std::chrono::milliseconds(500));
    t.request_stop();                    // cooperative cancellation
} // destructor calls request_stop() (if not already) + join() automatically — no leak, no terminate
```

Key differences from `std::thread`:

- Destructor automatically calls `.request_stop()` and `.join()` — you no longer must remember to join.
- If the callable's first parameter is `std::stop_token`, `jthread` passes one in automatically, enabling cooperative cancellation.
- `.get_stop_token()`, `.get_stop_source()`, `.request_stop()` are built into the `jthread` object itself.

## 2. `std::stop_token` / `std::stop_source` / `std::stop_callback`

Header: `<stop_token>`

The cancellation mechanism `jthread` is built on — but usable standalone too, e.g. to cancel work not tied to a `jthread`.

```cpp
#include <stop_token>
#include <thread>
#include <iostream>

std::stop_source stop_src;

void worker(std::stop_token stoken) {
    // Register a callback that runs the instant a stop is requested
    std::stop_callback callback(stoken, [] {
        std::cout << "Cleanup triggered by stop request\n";
    });

    while (!stoken.stop_requested()) {
        // do work
    }
}

int main() {
    std::thread t(worker, stop_src.get_token()); // plain std::thread + manual stop_token
    stop_src.request_stop();                     // triggers stop_requested() and the callback
    t.join();
}
```

- `stop_source` — the object that *issues* a stop request (`.request_stop()`).
- `stop_token` — a lightweight handle passed to workers to *check* for a stop request (`.stop_requested()`).
- `stop_callback` — runs a function immediately when a stop is requested (even if requested before the callback was registered).

## 3. `std::latch` — Single-Use Countdown Barrier

Header: `<latch>`

A simple, one-shot counter: threads count it down, and other threads can block until it reaches zero. Once it hits zero, it stays there — a latch cannot be reused or reset.

```cpp
#include <latch>
#include <thread>
#include <vector>
#include <iostream>

int main() {
    const int num_workers = 4;
    std::latch work_done(num_workers);

    std::vector<std::thread> workers;
    for (int i = 0; i < num_workers; ++i) {
        workers.emplace_back([&work_done, i] {
            std::cout << "Worker " << i << " doing setup\n";
            work_done.count_down();          // decrement once finished
        });
    }

    work_done.wait();                        // blocks main thread until count reaches 0
    std::cout << "All workers finished setup, proceeding\n";

    for (auto& t : workers) t.join();
}
```

Other members: `.arrive_and_wait()` (decrement, then block until zero — combines both operations), `.try_wait()` (non-blocking check).

## 4. `std::barrier` — Reusable Synchronization Point

Header: `<barrier>`

Like a latch, but **reusable** across multiple phases: once all participating threads arrive, the barrier resets automatically for the next round, optionally running a completion function between phases.

```cpp
#include <barrier>
#include <thread>
#include <vector>
#include <iostream>

int main() {
    const int num_threads = 3;
    std::barrier sync_point(num_threads, [] {
        std::cout << "-- Phase complete, all threads synchronized --\n";
    });

    auto work = [&](int id) {
        for (int phase = 0; phase < 3; ++phase) {
            std::cout << "Thread " << id << " working on phase " << phase << "\n";
            sync_point.arrive_and_wait(); // blocks until all 3 threads reach this point
        }
    };

    std::vector<std::thread> threads;
    for (int i = 0; i < num_threads; ++i) threads.emplace_back(work, i);
    for (auto& t : threads) t.join();
}
```

Other members: `.arrive()` (arrive without waiting, returns an awaitable token), `.arrive_and_drop()` (arrive and permanently reduce the count of participants for future phases).

## 5. Semaphores — `std::counting_semaphore` / `std::binary_semaphore`

Header: `<semaphore>`

A lightweight signaling primitive for controlling access to a limited number of resources, or for simple thread-to-thread signaling — often faster than a mutex + condition variable for these use cases.

```cpp
#include <semaphore>
#include <thread>
#include <vector>
#include <iostream>

std::counting_semaphore<3> pool_slots(3); // at most 3 threads may proceed at once

void access_resource(int id) {
    pool_slots.acquire();  // blocks if 3 threads already hold a slot
    std::cout << "Thread " << id << " using resource\n";
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
    pool_slots.release();  // free a slot for someone else
}

int main() {
    std::vector<std::thread> threads;
    for (int i = 0; i < 10; ++i) threads.emplace_back(access_resource, i);
    for (auto& t : threads) t.join();
}
```

`std::binary_semaphore` is just an alias for `std::counting_semaphore<1>`, useful for simple signal/wait handoffs between exactly two threads:

```cpp
std::binary_semaphore signal(0); // starts at 0 (not yet signaled)

void producer() {
    // ... produce data ...
    signal.release();  // signal that data is ready
}

void consumer() {
    signal.acquire();  // blocks until producer signals
    // ... consume data ...
}
```

Other members: `.try_acquire()`, `.try_acquire_for()`, `.try_acquire_until()` — non-blocking/timed variants.

## 6. Atomic `wait` / `notify` — Condition-Variable-Free Blocking on Atomics

Header: `<atomic>`

C++20 adds `.wait()`, `.notify_one()`, `.notify_all()` directly onto `std::atomic<T>` (and `std::atomic_flag`), letting a thread block efficiently until an atomic's value changes — without needing a separate mutex + `condition_variable`.

```cpp
#include <atomic>
#include <thread>
#include <iostream>

std::atomic<bool> ready{false};

void worker() {
    ready.wait(false);            // sleeps efficiently while ready == false
    std::cout << "Worker proceeding, ready flag observed true\n";
}

int main() {
    std::thread t(worker);
    std::this_thread::sleep_for(std::chrono::milliseconds(200));
    ready.store(true);
    ready.notify_one();           // wakes the waiting thread
    t.join();
}
```

- `.wait(old_value)` — blocks until the atomic's value is no longer `old_value` (avoids the "lost wakeup" problem of naive spin loops).
- `.notify_one()` / `.notify_all()` — wake one/all threads blocked in `.wait()`.
- Free-function equivalents also exist: `std::atomic_wait`, `std::atomic_notify_one`, `std::atomic_notify_all`.

`std::atomic_flag` also gained a non-destructive `.test()` method in C++20 (previously you could only `test_and_set()`, which always sets), plus the same `.wait()`/`.notify_one()`/`.notify_all()`:

```cpp
std::atomic_flag flag = ATOMIC_FLAG_INIT; // C++20: now also default-constructible to false: std::atomic_flag flag{};
bool currently_set = flag.test();          // read without modifying (new in C++20)
flag.wait(false);                          // block until flag becomes true
```

## 7. `std::atomic_ref` — Atomic Operations on Existing (Non-Atomic) Objects

Header: `<atomic>`

Lets you perform atomic operations on an ordinary object without changing its type to `std::atomic<T>` — useful when the object's layout must stay compatible with non-atomic code (e.g. shared with legacy APIs, or elements of an existing array).

```cpp
#include <atomic>
#include <vector>
#include <thread>

int main() {
    std::vector<int> data(10, 0); // plain ints, not std::atomic<int>

    auto increment_element = [&data](int idx) {
        std::atomic_ref<int> ref(data[idx]); // wraps the existing int atomically
        ref.fetch_add(1, std::memory_order_relaxed);
    };

    std::thread t1(increment_element, 3);
    std::thread t2(increment_element, 3); // safe: both go through atomic_ref on the same int
    t1.join(); t2.join();
}
```

The referenced object's lifetime must outlive the `atomic_ref`, and all concurrent accesses to that object must go through `atomic_ref` (or another atomic mechanism) for the duration — you can't freely mix atomic and non-atomic access to the same object at the same time.

## 8. Atomic `std::shared_ptr` / `std::weak_ptr`

Header: `<memory>`

C++11's free functions like `std::atomic_store(shared_ptr*, ...)` were awkward and easy to misuse. C++20 instead provides real specializations: `std::atomic<std::shared_ptr<T>>` and `std::atomic<std::weak_ptr<T>>`, with the same interface as other atomics.

```cpp
#include <memory>
#include <atomic>
#include <thread>

std::atomic<std::shared_ptr<int>> shared_state = std::make_shared<int>(0);

void writer() {
    auto new_val = std::make_shared<int>(42);
    shared_state.store(new_val); // atomically replaces the shared_ptr
}

void reader() {
    std::shared_ptr<int> local = shared_state.load(); // atomically obtains a copy
    if (local) { /* use *local safely */ }
}

int main() {
    std::thread w(writer), r(reader);
    w.join(); r.join();
}
```

This deprecates the old C++11 free-function API (`std::atomic_load(shared_ptr*)`, `std::atomic_store`, etc.) in favor of this cleaner, type-safe form.

## 9. `std::osyncstream` — Synchronized Output Streams

Header: `<syncstream>`

Multiple threads writing to `std::cout` concurrently can interleave characters from different `operator<<` chains. `std::osyncstream` wraps a stream buffer so that everything written through one `osyncstream` object is flushed as one atomic, uninterrupted block when the object is destroyed (or `.emit()`ed).

```cpp
#include <syncstream>
#include <iostream>
#include <thread>
#include <vector>

void print_report(int id) {
    std::osyncstream synced_out(std::cout);
    synced_out << "Thread " << id << " starting\n";
    synced_out << "Thread " << id << " step 1\n";
    synced_out << "Thread " << id << " done\n";
} // flushed as one atomic unit here — no interleaving with other threads' output

int main() {
    std::vector<std::thread> threads;
    for (int i = 0; i < 5; ++i) threads.emplace_back(print_report, i);
    for (auto& t : threads) t.join();
}
```

Without `osyncstream`, five threads calling `std::cout << ...` directly could produce garbled, interleaved output; with it, each thread's full block prints cleanly.

## 10. Coroutines — Language-Level Foundation for Asynchronous Code

Headers: `<coroutine>` (language feature: `co_await`, `co_yield`, `co_return`)

C++20 adds coroutines as a core language capability: a function can now suspend its execution and later resume, using `co_await` (suspend waiting on something), `co_yield` (suspend, producing a value, like a generator), or `co_return` (finish, optionally with a value). The standard library gives only the low-level machinery (`std::coroutine_handle`, `std::suspend_always`, `std::suspend_never`, promise-type customization points) — usable "return types" like a task/generator abstraction are left to libraries (many projects use `cppcoro`, or wait for C++23's `std::generator`).

A minimal generator-style coroutine, using a small hand-written promise type:

```cpp
#include <coroutine>
#include <iostream>

struct Generator {
    struct promise_type {
        int current_value;
        std::suspend_always yield_value(int value) { current_value = value; return {}; }
        std::suspend_always initial_suspend() { return {}; }
        std::suspend_always final_suspend() noexcept { return {}; }
        Generator get_return_object() { return Generator{std::coroutine_handle<promise_type>::from_promise(*this)}; }
        void return_void() {}
        void unhandled_exception() { std::terminate(); }
    };

    std::coroutine_handle<promise_type> handle;

    bool next() { handle.resume(); return !handle.done(); }
    int value() const { return handle.promise().current_value; }
    ~Generator() { if (handle) handle.destroy(); }
};

Generator count_up_to(int n) {
    for (int i = 1; i <= n; ++i)
        co_yield i;             // suspend here, producing i, resume on next call
}

int main() {
    Generator gen = count_up_to(5);
    while (gen.next())
        std::cout << gen.value() << " "; // prints: 1 2 3 4 5
}
```

Coroutines aren't multithreading by themselves — a coroutine can suspend and resume on a single thread. Their concurrency value comes from pairing them with an asynchronous I/O or scheduling library, where `co_await`ing a pending operation lets the thread do other work instead of blocking. Because the standard library provides only the building blocks (not a ready-made `task<T>` type), most real usage in C++20 relies on third-party libraries until later standards fill this in.

| --- | --- | --- |

| Coroutines (`co_await`/`co_yield`/`co_return`) | `<coroutine>` | Language-level suspend/resume for async code |

**Context:** this is by far the largest concurrency expansion of any standard since C++11 introduced threading at all. C++23 builds further on this foundation with `std::generator` (a ready-made coroutine-based generator type) and a handful of smaller refinements, rather than another wave of new primitives.
